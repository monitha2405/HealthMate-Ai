## 1. Executive Summary of the Project (The 2-Minute Pitch)

> "HealthMate AI is an intelligent healthcare decision-support and medical document analysis system developed as a full-stack web application. It addresses the challenge of patient health data fragmentation and medical jargon comprehension. Our platform incorporates five specialist LLM agents coordinated by a central orchestrator, a persistent PostgreSQL 16 database storing genuine Gemini embeddings in native JSONB columns with application-layer cosine similarity semantic search in Node.js, and deterministic clinical calculators for metrics like BMI and Mean Arterial Pressure. It provides immediate, login-free guest access using cryptographically secure random session tokens and HttpOnly cookies while strictly preserving guest data isolation and offering permanent, atomic multi-table data reset."

## 2. Core Academic Concepts & How They Are Implemented

### 1. Large Language Models & Prompt Conditioning
- **Model:** Google Gemini (`gemini-1.5-flash` configurable via environment variables) using the modern `@google/genai` TypeScript SDK.
- **Role:** Natural language generation, clinical summarization, and query reasoning.
- **Embeddings:** `text-embedding-004` generating dense 768-dimensional vector representations.

### 2. Multi-Agent Architecture vs. Monolithic Prompt
- **Why Multi-Agent?** A single monolithic prompt suffers from cognitive distraction and hallucination when asked to handle disparate domains simultaneously (e.g. interpreting an HbA1c lab report vs planning a vegetarian Indian diet).
- **Implementation:** The Central Orchestrator classifies user intent into 5 distinct domains (`document`, `trend`, `nutrition`, `wellness`, `general_knowledge`), routing queries only to the designated specialist agent.

### 3. Persistent Vector Retrieval-Augmented Generation (RAG) Without pgvector
- **Why PostgreSQL JSONB + Node.js Cosine Similarity?** Compiling and installing the `pgvector` C-extension on Windows workstations introduces severe platform hurdles (requiring Visual Studio C++ Build Tools or WSL). By utilizing PostgreSQL 16's native `JSONB` data type to store high-dimensional Gemini embeddings and computing cosine similarity via dot products in Node.js, we achieve genuine vector search with zero external C-dependencies.
- **Chunking Strategy:** Sliding window chunking (~400 words with 60-word overlap) ensures semantic continuity across chunk borders.
- **Cosine Similarity Equation:**
  $$\text{Similarity}(\vec{A}, \vec{B}) = \frac{\vec{A} \cdot \vec{B}}{\|\vec{A}\| \|\vec{B}\|}$$
- **Guest Scoping:** All vector queries enforce `WHERE de.guest_id = $1 AND hd.guest_id = $1`, preventing cross-user data leakage.

### 4. Deterministic Function Calling (Tool Use)
- **Why Tools?** LLMs are probabilistic token predictors and unreliable at arithmetic calculations.
- **Implementation:** Medical metrics such as BMI ($kg/m^2$), Mean Arterial Pressure ($Diastolic + \frac{Systolic - Diastolic}{3}$), and Mifflin-St Jeor caloric calculations are executed by deterministic server functions rather than generated by the LLM.

### 5. Login-Free Anonymous Session Security
- **Why Login-Free?** Removes all user friction. When opened in a browser, the application automatically provisions a 32-byte cryptographically secure random token, hashes it with SHA-256 before storage in PostgreSQL (`guest_sessions`), and transmits it via an HttpOnly cookie (`healthmate_session`).
- **Zero Admin:** No admin portals, credentials, or privilege escalation vectors exist in the codebase.

## 3. High-Frequency Viva Questions & Answers

### Q1: Why did you choose PostgreSQL without pgvector instead of Firebase, SQLite, or pgvector?
**Answer:**
"PostgreSQL 16 is a production-grade relational database with strict ACID guarantees, foreign key integrity, and connection pooling. We chose native PostgreSQL JSONB storage paired with application-layer cosine similarity calculations in Node.js because `pgvector` requires compiling C extensions on the operating system, which is error-prone on Windows workstations without Visual Studio Build Tools. This design delivers 100% portable, genuine vector RAG without external dependencies."

### Q2: How does your vector similarity search work?
**Answer:**
"We store our 768-dimensional embeddings generated by Gemini `text-embedding-004` in a `JSONB` column in `document_embeddings`. When a user asks a question, we compute its embedding with Gemini, fetch the authorized JSONB embedding arrays belonging to that guest from PostgreSQL using parameterized SQL, and compute the normalized dot product (cosine similarity) in Node.js. Sorting descending by similarity yields the top-K relevant chunks, which are then passed into the LLM prompt context."

### Q3: How do you prevent medical hallucinations?
**Answer:**
"We employ a three-tier defensive strategy:
1. **Document Grounding (RAG):** When discussing lab reports, the agent is strictly conditioned on retrieved excerpts from the user's uploaded reports.
2. **Deterministic Calculators:** Metrics like BMI, Mean Arterial Pressure, and caloric expenditure are computed by verified mathematical code rather than LLM text generation.
3. **Safety Guardrails & Disclaimers:** Prompt system instructions forbid diagnosing conditions or prescribing medications. Acute life-threatening symptoms (chest pain, stroke signs) are immediately intercepted by an emergency safety handler."

### Q4: How is patient privacy and multi-tenant data isolation enforced?
**Answer:**
"Every single query in the application uses parameterized SQL filtered by `guest_id = $1`. The guest ID is obtained exclusively by verifying the SHA-256 hash of the secure HttpOnly cookie session token stored in PostgreSQL. We never trust client-supplied user IDs or request headers."
